# Home Assistant

OpenWatts publishes retained JSON to its configured MQTT topic and creates MQTT
discovery entities under device identifier `openwatts`.

## User-facing entities

- battery voltage and estimated percentage
- battery state
- firmware version and device health
- Last Ride moving/elapsed time
- Last Ride average/peak power and cadence
- Last Ride revolutions and mechanical work
- Last Ride estimated distance and average/maximum road speed
- Last Ride end reason

Road values are published in SI-native units with Home Assistant device classes;
Home Assistant performs presentation conversion. Ride entities remain
unavailable until a valid ride exists. Intentional sleep does not mark the
device offline.

## Reporting lifecycle

Battery checks and MQTT reports are independent. Stable battery checks remain
silent unless policy requires a state, voltage, retry, or heartbeat report.
A completed Last Ride is persisted with durable pending state and is published
during the next bounded pre-sleep or otherwise permitted report opportunity.
QoS 1 acknowledgement clears that state; failure never prevents sleep.

## Dashboard

The storage dashboard is **OpenWatts** at `/openwatts-dashboard/status`. It is
phone-first and contains Device, Battery, Last Ride, and meaningful history.
The optional Ollama ride perspective is generated by Home Assistant from
deterministically calculated comparisons; it does not alter device data.

The network path must permit OpenWatts to reach the configured broker TCP port.
Use the Settings page to match the device to the deployment LAN.
